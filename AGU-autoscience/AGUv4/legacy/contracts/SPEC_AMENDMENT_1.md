# SPEC Amendment 1 — the null, the scorer chain, and two overclaims

Status: **WRITTEN BEFORE ANY v2 RESULT EXISTS.** Archived under `legacy/contracts/`. Amends `SPEC.md` revision 3. Live entry point: `../../README.md` + `../../REPORT.md`.
Author: Claude, for Ezekiel Barnett · ACCORD · 2026-08-06

---

## 0. Why this amendment exists

Review of the v1 implementation found three defects. Two are verification gaps and one is
a design error in the null. All three are fixed here, and every rule below is fixed
before v2 produces a number.

- **The v1 legacy check never verified the published headline.** AGUv3's claim is
  `P(dry | −WVG) = 0.79` and `+La Niña = 0.77`, at **k=3 and k=4**. v1's check read the
  **k=2** table, found 0.71 / 0.69, and labelled it "the eastern zone's MAM conditional
  rates" — a different quantity at a different level. The 22 hierarchy rows were compared
  only on their window columns, so the statistics at k=3 and k=4 went unchecked entirely.
- **SPEC §16 names three scorer-agreement links and v1 ran one.** The atlas fast-vs-slow
  link ran; the two inherited links — batched vs per-cell, and per-cell vs the locked
  `bench.evaluate` — were inherited as code and never executed in this project.
- **The v1 null could splice wrapping seasons.** It permuted the rainfall field by whole
  calendar years. A season is not a calendar year: NDJ takes November and December from
  year Y−1 and January from year Y, so after a calendar-year permutation those halves come
  from unrelated donor years and the null's outcomes are seasons that never occurred.

**Neither v1 number nor either of the two smoke-null replicates was used to choose among
methods.** Every rule below is justified on its own terms.

## 1. The legacy reproduction claims exactly what it verifies, and no more

### 1.1 The ARI = 1 claim is withdrawn

SPEC §9.1 Tier 1 promised "zone labels agree cell-for-cell (ARI = 1.000 against a stored
reference label vector)". **There is no such vector.** AGUv3's `data/` directory was never
committed — it holds only a README saying the NetCDFs are regenerated by the fetch
scripts — so `zones.nc` does not exist and never did in this checkout. The claim was
unsupportable when written. It is removed.

### 1.2 What Tier 1 actually establishes

Identity of the zonation is established by agreement on every published summary of it,
each checked against AGUv3's own tables:

| quantity | tolerance |
|---|---|
| k=2 cell counts (1144, 2420) | exact |
| k=3 cell counts (877, 1112, 1575) | exact |
| k=4 cell counts (450, 847, 731, 1536) | exact |
| k=2, k=3, k=4 centroids | 0.05° / printed precision |
| bootstrap ARI curve, k = 2…8 | 0.005 |
| silhouette curve, k = 2…8 | 0.005 |
| discovered window month-sets at every level | exact |
| within-country orientation η², all levels | 0.005 |

That is strong evidence of the same partition and it is what the reproduction reports. It
is *not* a cell-for-cell label comparison, and the report says so.

### 1.3 Tier 2 now checks the published headline directly

Added, and required to pass:

- **k=3, eastern zone 2, MAM: `P(dry | −WVG) = 0.79`, `+La Niña = 0.77`, n = 13.**
- **k=4, eastern zone 3, MAM: `P(dry | −WVG) = 0.79`, `+La Niña = 0.77`, n = 13.**
- **every statistic in all 22 hierarchy rows** (`sym`, `droc`, `pclim`, `pneg`) to 0.01,
  and the conditional-rate column compared string-wise including its `n`.
- **The k=2 value is 0.71 / 0.69 and is reported as such**, explicitly distinguished from
  the published headline rather than presented as it.

## 3. The primary null is a complete-season target permutation

### 3.1 The rule

1. **Zones and windows are discovered from each fold's UNPERMUTED training rainfall.**
2. **All 200 permutations come sequentially from one `numpy.random.default_rng(4242)`**, so
   replicate *r* is reproducible and every arm and family is paired on the same draws.
3. **The same year permutation is applied to every complete zone-window seasonal target
   series in the fold**, preserving cross-zone and cross-window donor-year alignment.
4. **SST is untouched, so condition membership is untouched**: a test year is a La Niña
   year in the null exactly when it is one in the real run.
5. **Predictor and lead selection, the regression, the residual spread and the tercile
   thresholds are all re-fitted inside every replicate.**

### 3.2 Why discovery is not permuted

The null exists to price a **skill-selected** search. Zone discovery and window detection
consult neither SST nor any score — they see rainfall alone — and SPEC §10 forces every
discovered zone-window into the report, so nothing survives because it scored well.
Discovery is therefore not a skill-selected axis and there is no selection there to pay
for. The axis that is skill-selected is **predictor and lead**, chosen by inner LOYO from
20 candidates per zone-window, and the null re-runs exactly that.

**This narrows what the null licenses, and the report must say so.** The p-value prices
predictor and lead selection. It does not price the choice of feature blocks, τ, the
detector, or the two-window cap — none of which are searched — and it no longer prices
zone discovery, which is not selected on skill.

### 3.3 Donor-year alignment and the shared support

Windows differ in usable years: a deep lead on MAM reaches October–November of the prior
year and so loses 1981, while OND does not. One donor map cannot be valid for two
different supports, so **every zone-window in a fold is restricted to the fold's common
usable year set**, and the donor map is the rank-restriction of the single permutation to
that set.

- **No test year is lost.** The earliest walk-forward test year is 2002.
- At most one early training year is dropped from windows that would otherwise have had it.
- **The real run uses the identical restriction**, so real and null share their support
  exactly and differ in one thing only: whether the target series is permuted.

### 3.4 The calendar-year field permutation is retained as a labelled sensitivity analysis

It is reported as `sensitivity_field_perm`, always with this sentence attached: *a
calendar-year field permutation cannot preserve complete outcomes for wrapping windows,
because NDJ splices November–December from one donor year with January from another.* It
adjudicates nothing.

### 3.5 Compute

Discovery now runs six times per protocol rather than 1,200 times. The sweep cost is
dominated by 200 replicates × 6 folds × selection-and-scoring. The 4-hour ceiling stands
with large margin.

## 4. The `zones-shared` selection rule, locked as implemented

Fixed before any v2 result, and exactly what the code does:

```
for each (window, fold):
    for each candidate key in FEATURE_KEYS:                      # 20 = 5 indices x 4 leads
        pooled[key] = SUM over zones z in this window of
                          omega(f, z, window) * min( LOYO_MSE(key, z) / Var_train(y_z), 1e6 )
    chosen = argmin(pooled)                                      # one key for every zone
```

- **Area-weighted** by `omega(f, z, window)`, the same complete-atlas weight §10 pools with.
- **Variance-normalised**: each zone's LOYO MSE is divided by the variance of that zone's
  training target, so a wet zone cannot dominate a dry one.
- **Cap: `1e6`** applied to the normalised ratio, so a degenerate predictor cannot make the
  pooled objective infinite and destroy the comparison.
- **Tie-breaking: `numpy.argmin` returns the first minimum**, and `FEATURE_KEYS` is ordered
  index-major then lead-minor, indices in the order `nino34, iod, wpg, wvg, iwhg` and leads
  `0, 1, 2, 3`. A tie therefore resolves to the earliest index in that list and then the
  shortest lead.

No alternative pooling rule was evaluated, and none may be substituted on the basis of an
observed score.
